# zzlibrary 需求说明

> 个人多端资料管理与阅读器（个人资料库）。本文档是开发过程中所有迭代的唯一需求依据，需求变更须同步更新此处。

## 1. 项目定位

面向个人的图书/文献/文档/报告/资料管理系统（**个人资料库**），核心特色是**虚拟图书馆书架**浏览方式（Y-Z 侧视 / X-Z 比例时间轴多视图）。部署在个人电脑上，局域网内多端访问。界面定位用语：副标题「个人资料库」、首页/导航第一项「馆藏」；书架/书脊/入库等图书馆隐喻保留。

- **形态**：Web 应用（PC/平板/手机浏览器）+ 原生移动 App（React Native + Expo，App 内也提供完整 3D 书架）
- **后端**：Python FastAPI + SQLite，单服务承载 API 与文件服务
- **访问**：局域网 + 单账号密码（HttpOnly 会话 Cookie）
- **使用语言**：界面为中文

## 2. 入库与资料包（Package）模型

资料库的最小单位是**资料包**（书架上一格书脊 = 一个包）：一个包可包含任意数量/类型的文件——图书/文献/文档/报告/**视频/音频/图片/任意格式**。典型场景：一次视频会议的录屏 + PPT + 纪要整包入库。**单文件包的包名默认为文件名**；多文件包需用户命名。这让资料库成为「大一统知识管理与阅读库」。

- 主要方式：**网页上传，一次入库一个包**：多选/拖拽文件（可混合格式）→ 后端逐个暂存并抽取元数据 → 本次上传的**所有文件同属一个资料包**（**拖拽区常驻且空态/有文件同一根矮条**，继续拖拽/点击追加，无需切页）→ 单文件包名默认文件名、多文件包需命名、首个文件的抽取元数据预填表单 → 一张表单填包元数据 → 入库 → 成功页（查看列表/再入一包）。放弃（移除文件/离开页面）即废弃对应暂存
- 包元数据：包名（必填）、作者、发布方、**多条分类路径**（每条 = 一级[必选]/二级[可选]/三级[可选]，层级逐级对应；一个包可同时属于多个书架位置，如「技术/会议」+「文学/小说」）、**发布/发版时间**（可为空，支持 前221 / -221 / YYYY / YYYY-MM / YYYY-MM-DD，公元前按天文习惯无公元 0 年）、标签、备注
- 多路径计数语义：书架聚合按 **(包, 二级, 三级) 三元组去重**——同一包多条路径落在同一书架只算一本；组/一级分类的 total 按去重后的包数统计；列表筛选 = 任一路径命中，「未分类」= 无任何路径
- 分类未填不丢弃：进入「未分类」分组（资料包列表可按「未分类」筛出补全）；发布时间未填：不上 X-Z 发布时间轴（**上架 = 分类 + 时间齐全**，资料包列表可按「未注明时间」筛出补全——编目完善后才在架上出现；入库时间轴不受影响，created_at 必有）
- 上传两步：`stage`（暂存+抽取）→ `commit`（多文件组包正式入库）；暂存清理三重规则：**主动废弃**（`POST /stage/discard`——向导里移除文件、离开入库页、编辑弹窗加文件失败时前端立即调用）+ commit/add_file 成功即清 + **24h TTL**（每次上传懒清理 + 后端启动兜底清扫）；已入库的包可继续**加文件/移除文件/重命名**（编辑弹窗为**事务式**：文件增删先挂本地——新文件停在暂存、移除只做标记，点保存才落库；点取消全部撤销，新文件的暂存立即废弃；**移除至空包时保存=删除整个资料包**（红字持续警示 + 保存时一次确认——确认门只设在不可逆的一步，标记本身可撤销不重弹）；直接调 API 移除最后一个文件会被 422 拒绝）
- 包封面 = 包内第一个有封面的文件（EPUB 内置封面 / PDF 首页 / 图片自身），否则书名占位封面；书脊贴图逻辑同前
- 阅读进度**按文件记录**（EPUB=CFI、PDF=页码、文本=百分比、媒体=播放位置）
- **包状态语义（M3.11 已实施）**：保留 `packages.status` **存储列 + 写入时增量重算**（写入低频、列表/书架/筛选高频，且状态筛选需索引——不宜改为查询时纯函数全量聚合）。规则：任一可读文件在读→在读；全部可读文件读完（≥98%）→已读；**不可读格式（zip/bin 等无阅读深度格式，即非 KNOWN_FORMATS）中性，不参与聚合**；无可读文件的包 status=""（界面显示「—」，不参与状态筛选）。重算触发点=写进度 + **包内文件增删** + 入库（`app/services/status.py`）。**手动编辑状态已取消**（PATCH status 字段移除，前端编辑弹窗无状态下拉）。启动时存量对账：lifespan 全量重算一遍（幂等，规则演进/历史手动值归位）。M4 配套：进度表加 updated_at（「继续读/最近在读」入口）；包级完成度显示（如「2/3 已读」）
- **入库不限格式**（个人资料库不替用户挑文件）：已知格式按下表抽取元数据/封面；未知扩展名原样登记为 format（清理为字母数字 ≤12 位），无扩展名记 `bin`，仅登记（占位封面 + 下载），文件选择器/拖拽均不做类型限制
- 支持格式与深度：
  | 格式 | 元数据 | 封面 | 阅读深度 |
  |---|---|---|---|
  | EPUB | ebooklib | 内置封面 | 内置阅读器（深度，M4） |
  | PDF | pypdfium2 | 首页渲染 | 内置阅读器（深度，M4） |
  | TXT / Markdown / HTML | chardet/标题抽取 | 占位封面 | 内置阅读器（深度，M4） |
  | docx / pptx / xlsx | python-docx/pptx/openpyxl | 占位封面 | 在线预览 + 下载 |
  | 视频 mp4/webm/mov/m4v/mkv | 文件名 | 占位封面 | 浏览器原生播放（不转码；不兼容容器提示下载） |
  | 音频 mp3/m4a/wav/ogg/flac | 文件名 | 占位封面 | 原生播放 |
  | 图片 jpg/png/gif/webp | 文件名 | 图片自身 | 原生显示 |
  | 其他任意格式（zip/源码/工程文件…） | 文件名 | 占位封面 | 下载（已知扩展名未来可按需加深） |

## 3. 虚拟书架浏览（核心特色）

进入某个**一级分类**后默认以虚拟书架方式展示。**书架以资料包为单位**：一格书脊 = 一个包；**书脊厚度统一**（不随文件数变化，文件数用角标表达）。

**轴系 v2（2026-11-03 与用户确认）**：三个轴全部承载语义维度，数量由架上的书直接体现：

- **X = 时间轴**：书按发布时间在**弹性时间轴**上落位（书多的年代长、书少的年代短），单行自然间距
- **Y = 二级分类**：一组一架，沿排向依次排开（组牌显示分类名与包数）
- **Z（竖直）= 三级分类**：一架之内每层是一个三级分类（左侧竖排架签；"未细分"为独立层）
- **结构隐喻**：每座书架 = 一个二级分类；层 = 三级分类；书按发布/发版时间归入对应年代的横向位置
- **两个正交视图**（CSS 渲染，"书房"设计语言）：
  1. **Y-Z 排视图（默认）· 书架侧面**：实体书架侧板的样子——**一架 = 一个二级分类**（顶铜牌），一整块木侧板看不见书，横隔板**板沿**一条条，板沿之间贴**插卡式标签牌**（三级分类名 + 藏书数）→ 多座书架并排（底部对齐），对比各分类的三级构成与体量；点书架进正面时间轴
  2. **X-Z 时间轴（书架正面）· 弹性时间轴长卷，双模式，单行制（M3.16 重制，取代 M3.13e 时间窗自适应）**：**长卷模型**——全架共享一条**弹性时间→x 映射**：逐区间尺度 s = max(横跨该区间的各层段带 内容宽/时长)，各层皆无书的时代空档压成固定窄条（24px，虚线竖标悬停示年跨「907 → 960 · 53 年无产出或未收录」）；映射一次算定 → **长卷固定**（反向：左 = 离现在最近，scrollLeft=0 即最新端）。**拖拽 = 原生滚动**：内容 1:1 跟手，书脊位置建卷时定死、永不重排——**不闪现、不消失、不挪窝，进出只由视口边缘扫过决定**（此前时间窗模型的三个顽疾：窗口两边乱动、书从轴中部冒出、有空位却不见书——全部消失）。段带宽 = 该段年代的弹性积分宽 **≥ 本层内容宽**（尺度函数保证）→ **单行自然间距恒成立**，同一天几百本也只是段带变长（全部可读可点，不再有"墙+3.6px 色块"）。书在段带内**按日期比例落位 + 最小间距前推**：密则自然间距铺满、疏则拉开。映射全层共享 → **跨层大致同期对齐**（区间级：隋唐被撑宽的年代区间在东罗马行也是同样的 x 区间，疏密竖向可读——演示数据实测拜占庭段 533–2855 完全包住隋唐段 1101–2772；对齐粒度=区间而非年份，书在段内是比例位置）。**窗口/锚点/可行性二分机制整体删除**（头部显示「视口 X – Y · 全范围 …」由长卷映射反查）；点左侧架签选段跳转 = 滚动定位到该段新侧（瞬时）；书脊大小按钮变化后重建长卷；滚轮纵向原生浏览。**未注明时间的书不上时间轴**（M3.14：上架=分类+时间齐全，资料包页按 未注明时间/未分类 筛出补全；架签计数=有日期的书，悬停提示另有几本未注明）。头部「按发布时间 / 按入库时间」切换（切轴回最新端）：
     - **发布时间（默认）**：各层用自己的分段标注带（「1368–1644（明）」，放不下优先别名）；段间空档（各层皆无书）压成窄条悬停示年跨；跨层同一 x 区间≈同一时代（大致同期对比）；未注明时间的书不上时间轴
     - **入库时间**：横轴 = created_at，**所有层共用自动日历分段（零配置）**——按全范围跨度自动选粒度：≤2 月按周（周一对齐）、≤2 年按月、≤8 年按季、更长按年（段标签自描述如「2026年11月」，窄段回落紧凑别名）；跨层同月同列；**无「未注明时间」列**（入库时间必有）；空档 = 该时段未入库；悬停卡显示入库日期
- **设计 Token**：暖纸底 #f4efe4｜木色 #7a5c3e/#96754f/#b99a72｜铜牌 #a8874f→#c9a86b｜书影=按包主色（id 散列色相）｜标题/名牌/架签用衬线（Noto Serif SC/宋体），正文系统黑体
- **交互**：按住拖拽=平移长卷（**内容 1:1 跟手**：向左拖看更早；纵向滚动楼层；拖动 >4px 吞掉 click 防误触书脊）；点左侧架签=该层时间段列表跳转（滚动定位）；普通滚轮=原生上下浏览；书脊大小缩放按钮（变化后重建长卷）；悬停书脊 250ms 出预览卡（封面/作者/年代/文件数/状态，不用点开抽屉）、点击书架进入架内视图、点击书弹出详情卡（封面/元数据/阅读入口）、视图切换按钮；Y-Z 多架**顶牌对齐**（层数多的架向下延伸不破坏对比），标签牌含数量填充条（相对藏书量）；二级分类多→左右滑动、三级分类多→上下滑动，**不做压缩式紧凑模式**
- **视口窗口化（虚拟化）**：Y-Z 只渲染视口 ±2 架（占位块撑滚动条）；X-Z 楼层纵向窗口化 + 横向按视口裁剪（视口外的层/段带/书脊不渲染）+ 贴图 lazy；**布局引擎（timelineLayout.ts，M3.16 弹性长卷）**：建卷一次 O(书数+段数·log)（预计算毫秒沿用 M3.15），**滚动时布局零计算**（原生滚动合成，实测拖拽 0 长任务）——比时间窗模型（每拖拽帧 ~4.6ms 布局）更轻；数据传输（with_packages 全量 payload）留 M6 按架懒加载
- **时间分段（按层独立）**：生效优先级 **三级分类覆盖 > 二级分类覆盖 > 全局默认**（未细分层跟随二级）；模式：按年 / 每 N 年 / 按十年 / 按月 / 自定义区间（起止支持 YYYY / YYYY-MM / YYYY-MM-DD，**可带别名**如朝代、时期名）；自动模式以该层实际最早~最晚日期截断；组（二级分类）的统一时间范围 = 各层分段并集 ∪ 藏书日期（比例时间轴跨层对齐的基准）；区间之外的书仍按日期显示在无标注区域
- **书脊视觉**：书脊贴图（竖排书名 + 封面主色底）由**后端 Pillow 预渲染**为 PNG，Web 与 App 只加载纹理（双端一致，规避 expo-gl 文字渲染难题）
- **体量表达**：段带/年代上书脊的密集程度直接体现体量；弹性长卷下段带宽≈同期最密层的书量（书多的年代长），同层书距拉开=同期他层更密（对比信息）
- **时间边界**：发布时间支持公元前 9999 ~ 公元 9999（公元前写「前221」，无公元 0 年）；内部存储用 9 补码序键（前1→-9999）保证字典序=时间序，API 出入参自动转换为人类可读形式
- **性能**：CSS 渲染 + 贴图懒加载，个人量级（数千册）流畅

## 4. 阅读器

- Web 内置：EPUB（foliate-js，中文排版优先；备选 epub.js）、PDF（pdfjs-dist，流式加载）、TXT/MD/HTML 统一分页阅读器、docx（mammoth 转 HTML 预览）、pptx/xlsx 轻预览+下载
- **进度多端同步**：EPUB 存 CFI、PDF 存页码、文本类存百分比；状态自动流转 未读 → 在读 → 已读
- 移动 App 阅读第一期以 WebView 加载 Web 阅读页实现（天然同步），后续再评估原生 PDF 优化

## 5. 管理功能

- 图书列表：按一级/二级/三级分类（含「未分类」）、格式、状态、发布时间（含「未注明时间」——编目补全入口）、关键词筛选、搜索、排序、分页；编辑元数据；删除（连带文件与缓存图）
- 分类管理：树形增删改、移动、排序（有子分类时不允许删除；删除时书中对应引用置空）
- 时间分段设置：全局默认 + 按二级分类覆盖
- 统计与批量编辑、元数据导出备份：M6 打磨

## 6. 非功能需求

- 数据全部本地：SQLite（`data/library.db`）+ 原件（`data/files/`）+ 封面/书脊缓存（`data/art/`）+ 暂存区（`data/staging/`，24h 自动清理）
- 备份 = 直接拷贝 `data/` 目录
- 单账号：环境变量配置用户名/密码；会话 30 天
- 开发环境：Windows，Python 依赖装入 `C:\Users\wenjch\wenjch\pyenv\base\.venv`（uv 管理）；Node ≥ 20；Vite 代理 `/api` → FastAPI:8000；生产由 FastAPI 托管 Web 构建产物

## 8. 开发记录

- **2026-11-04 入库向导重构（一次一包）**：用户拍板"一次入库一个包，上传的所有文件都属于这个包"。UploadPage 从多包组织模式（每文件默认成包+合并所选+✕拆出+应用到全部包+N 张包卡）重写为单包模式：文件清单 + 一张包信息表单 + 入库按钮；单文件包名自动预填（用户改过则尊重输入）、多文件需命名；首个文件的抽取元数据预填一次（ref 防后续文件覆盖用户输入）；成功页提供"查看列表/再入一包"。暂存登记/放弃即删/pagehide 兜底全部保留。e2e：双文件注入→表单预填→命名→入库→库中 1 包 2 文件→清理无残留。多包批量操作（应用分类到全部包等）随场景一并移除。追加修复：拖拽区**常驻**（此前选完文件即消失、追加只能点「继续添加」，上传能力被劈成两页）——有文件后压缩为 h-24 矮条，拖拽/点击继续可用。
- **2026-11-04 入库向导三连修**：用户实测①双文件上传只显示一个②组织页文件默认未勾选③质疑"应用到全部包"无用。根因①是经典 React 文件陷阱：`addFiles` 异步循环里每轮 `Array.from(files)[i]` 重读**活的 FileList**，首个文件暂存成功 → setGroups 重渲染 → `<input>` 在两个条件分支间被卸载重建 → FileList 清空 → 第二个文件取到 undefined 上传失败。修复：入口立即快照 `const list = Array.from(files)`，循环用快照；input value 用后重置（可重复选同名文件）。②进入组织页默认全选（多数意图是"这批合成一包"，点「合并所选」即达）。③非无用——是多包批量填元数据的捷径，此前被 bug ①掩盖。DataTransfer 注入 e2e：双文件均暂存 ✓ 两张包卡 ✓ 默认勾选 2/2 ✓ 离开页面即废弃暂存（staging 归 0）✓。
